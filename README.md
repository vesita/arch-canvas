# arch-canvas · 架构画布

人与 AI 共用**同一张 Mermaid 架构图**的 DSH 插件。

用户在主窗口「架构画布」子页上直接拖节点、拉连线、改属性；AI 读到的是同一张图的 Mermaid 文本。
用户在图上动一下，AI 下一步就能看见；AI 改一处，用户那边立刻跟着动，**而且能看到它改的是哪几个节点**。

```
   ┌────────── 用户 ──────────┐        ┌─────────── AI ───────────┐
   │  主窗口「架构画布」子页   │        │  每步注入的上下文里就有图  │
   │  拖拽 / 连线 / 改标签     │        │  arch_read / arch_edit    │
   └───────────┬─────────────┘        └────────────┬─────────────┘
               │  doc:set（整个图模型）             │  arch_edit（增量 op）
               ▼                                   ▼
         ┌───────── host 侧唯一真相源 ─────────┐
         │  图模型 ⇄ Mermaid 文本；写盘 <项目>/.arch-canvas/<图名>.mmd │
         └────────────────────────────────────┘
```

## 这是什么

**源文本是唯一真相。** 图模型是编辑对象，Mermaid 文本是交换格式 —— 不是「渲染 Mermaid 再去改 SVG」，
那条路走不通：flowchart 不支持手工坐标，布局引擎每次都会把你的摆放重算一遍。

- 图存在项目图库：`<项目>/.arch-canvas/<图名>.mmd`，一张图一个文件。
- 坐标（`%% @pos`）与代码锚点（`%% @file`）寄生在 `%%` 注释行里，所以这个文件到哪都仍是**合法 Mermaid**，
  能直接贴进任何支持 Mermaid 的工具。
- AI 默认只发增量 op（`arch_edit`），不动你摆好的布局。

### 四个词

| 词 | 指什么 |
|---|---|
| **源文本** | 那份 Mermaid 文本 —— 唯一真相 |
| **画布** | 面板里可拖拽、可连线的视图；任何改动最终都落回源文本 |
| **上下文** | 每一步自动注入给 AI 的那份源 |
| **锚点** | 从图上元素连到源码文件 / 符号的线（`%% @file`）；它会腐烂，所以每次加载都重算状态 |

两侧的名字也是固定的 —— **不要用「前端 / 后端」**：那会让人联想浏览器与服务器，
而这两半都跑在你自己机器上，区别只在职责。

- **画布端**（`src/client/`）：渲染、拖拽、检查器、导出。
- **解析端**（`src/host/`、`src/package/`、`src/bootstrap/`）：解析、落盘、锚点校验、给 AI 同步上下文。

代码标识符仍叫 `client` / `host`，不改。

## 装上

`arch-canvas` 是标准 dsh 插件包（`package.json` 声明 `dsh.bundle.patch` 与 `dsh.client`），
用 `dsh plugin` 管理，不用手改任何 yml：

```sh
cd /home/vesita/coding/my/arch-canvas          # 仓库根目录
dsh plugin --profile web add  "$PWD"           # 装开发目录（链接部署）
npm run pack                                   # 打 tgz，落点 ${DSH_HOME:-$HOME/.dsh}/packages
dsh plugin --profile web add  "${DSH_HOME:-$HOME/.dsh}/packages/arch-canvas-0.6.11.tgz"   # 装分发包（快照）
dsh plugin --profile web update arch-canvas
dsh plugin --profile web remove arch-canvas
```

版本号取自 `package.json`（当前 0.6.11）。`dsh plugin` 是 pnpm 的转发器：在 profile 里跑 pnpm，
再按安装结果对齐 `dsh.profile.bundles`。目录依赖（`link:`）给的是符号链接；
`file:...tgz` 是**把包解成真目录的快照**。

不装包也能跑的**动态 Cordis Package 形态**（引导层读盘 `dist/`）作为开发 / 演示路径保留，机制与沙箱约束见 `AGENTS.md`。

### 改代码怎么生效

**先查清本机是哪种部署**，它决定下面每一行：

```sh
grep arch-canvas ~/.dsh/profiles/web/package.json    # file:...tgz = 快照；link:... = 链接
ls -l ~/.dsh/profiles/web/node_modules/arch-canvas    # 真目录 = 快照副本；符号链接 = 指向项目
```

| 改什么 | 链接部署 | 快照部署 |
|---|---|---|
| `src/client/*` | `npm run build` → **刷新页面** | `npm run build` → 拷 `lib/ui.js` 进安装目录 → **刷新页面** |
| `src/host/*`、`src/package/*` | `npm run build` → hmr 重挂 | `npm run build` → 拷 `lib/*.js` 进安装目录（或重装 tgz）→ **重启 dsh** |
| `src/bootstrap/*` | 动态 Package：重新 `cordis_define` + `cordis_run` | 同左 |

**本机（profile `web`）当前是快照部署**：`node_modules/arch-canvas` 是真目录，`npm run build` 对运行态零影响。

**`plugin.mount` 不是生效证据** —— 快照部署下 hmr 重挂的是快照里的 `lib/index.js`，日志照样多一行，
跑的却还是旧代码。验活要打一次真 RPC：

```sh
curl -s -X POST http://127.0.0.1:3080/arch-canvas/rpc -H 'content-type: application/json' \
  -d '{"method":"doc:get","args":{"where":"<项目目录>"}}'
```

**半新的客户端最危险**：`lib/ui.js` 是宿主每次请求现读磁盘的，界面已经是新的、宿主还在内存里跑旧的 ——
旧宿主会**静默丢掉**新界面发来的字段。上线顺序：`npm run build` → `npm run pack` → 重装 tgz → **重启 dsh**。

## 界面上能干什么

工具条上的画布工具：拖节点、拉连线、改形状 / 分组、撤销重做、导出 `SVG` / `PNG` / `复制源码`、
`图库` 切图、`历史 N` 看检查点。

**AI 动过的节点会在画布上脉动高亮 5.2 秒**（描边转金 + 一圈扩散的环），改图回执里也会写明。
你自己的改动不高亮。

### 在元素上留言，指着它说话

选中节点 → 检查器里写留言，节点左上角出现琥珀色笔角标。
留言挂在节点 id 上、存在图同目录的 `notes.json` 里，**不写进源文件**。

- **指代明确**：AI 不用再猜「第二个方框」是哪个节点。
- **一次投递**：AI 读到一次就消耗掉，不会反复出现；工具栏「留言 N」里待递在前、历史在后（最多 6 条），
  点一行定位到那个节点，想让某条重发就点「再送一次」。
- **未办留言由宿主每一步注入给 AI，不经过输入框**；长期挂着的意图不要放留言（投递一次就没了），
  那应该写进节点描述。
- **删节点不丢留言**：留言独立于源文本。
- **发送入口**：留言清单头部「交给 AI (N)」把整批一次交出去 —— 输入框空着也行
  （它替你把这批写成一条消息再发），你已经打了字就原样发你那句。检查器里还有单节点「发送给 AI」。
- 聊天输入框里可以用 `@` 引用画布节点，展开它的模型文本。

### 把方块钉到代码上

```mermaid
%% @file n1 "src/host/mermaid.ts#parseMermaid"   ← 这个节点对应哪段源码（一个节点可多条）
%% @summary "画布 ↔ 宿主 ↔ AI 之间的那条链路"     ← 整张图的一句话总结（图级，不挂节点）
```

- **`@file`（代码锚点）**：检查器里填 `路径` 或 `路径#符号`，一行一条。
  它捕的是**「中文标签 ↔ 英文路径」这个 grep 不出来的映射**。每次加载 / 保存都真去校验，
  结论摆在两处：节点右下角 `▤` 角标（失效变红）、检查器里逐条 `✓ / ⚠ 文件不在 / 符号不在`。
  进提示词时失效的带 ⚠ 并明说「不要照着用」—— 一条过期锚点比没有锚点更坏，它会把 AI 自信地送到错的文件。
  判不了根（全局图库里的图）时标 `无法判定`，不假装没问题。
- 还有一层锚点自己看不见的腐烂：文件还在、符号还在，但那段代码在图上一次落盘之后被改过。
  它靠**内容指纹**比出来 —— 角标转琥珀、画布顶部出一条「这张图可能已经过期」。
  同一处还会报**漏画**：哪些目录有源码、却没有任何锚点指向（它只是「还没画」，语气低一档，不是报错）。
- **`@summary`（一句话总结）**：写在文件头部一行，进提示词时单列成「**这张图讲的是**」；
  图库选择器与起始页里它就是那张图的副标题。

两者都**随节点存活**：节点删了，锚点跟着消失；AI 整体重画（`arch_write`）时按节点 id 继承下来
（你自己改源码页则一律以新文本为准 —— 删掉那一行就是真的删）。

### 图库与图引用

图库**跟着项目走**：每个项目目录下一个 `.arch-canvas/`，一张图一个 `.mmd`。
项目路径来自会话的 cwd，所以人和 AI 落在同一个图库；识别不出 cwd 就回退全局图库 `~/.dsh/arch-canvas/`，
提示词里会写明当前用的是哪个。

**图库不会自动创建。** 没有 `.arch-canvas/` 时读路径**一个字节都不写**：画布就是空的，面板与提示词都会说明。
要建只有两条显式入口 —— 面板上的「新建并打开」，或 AI 在**征得你同意**之后的 `arch_switch { create: true }`；
在那之前 `arch_write` / `arch_edit` 会被硬拒绝（错误信息里写明原因）。

**图引用一律用「相对项目根的 key」**，只此一条规则（按路径打开的外部文件例外：它的 key 就是路径）：

| key | 含义 |
|---|---|
| `架构` | 根图库里的 `架构.mmd` |
| `支付/对账` | 子项目 `支付` 的图库里的 `对账.mmd` |

`arch_switch` / `arch_read` 的 `diagram`、`set_link` 的 `link` 都用这个写法。
节点上的 `%% @link <节点id> <key>` 是**下钻**：这个节点展开就是那张图；画布上带 `↗` 角标，点它跳过去。

**项目里散落的 `.mmd` / `.mermaid` 也能打开**（扫描时顺手收下）：点一条就是按路径打开，
之后改动写回那个文件本身。`.md` 里的 mermaid 代码块**不扫** ——
回写文档里的某一个代码块，语义与风险都不是「打开一个文件」这一档。

**删除是软删除**：文件顶部写一行 `%% @deleted`，选择器里不列它（「已删除」区可一键恢复），
**文件和内容永不丢**。改名 = 新建 + 旧名软删，且不能跨图库。

**面板入口**：工具条「图库」按钮列出当前项目图库里的图（key、节点 / 连线数），点一条切过去；
每条后面有「改名」「删除」（删除要再点一次确认），底部「已删除」区可恢复，
输入框可新建（名字可以是 `子项目/图名`）。切图时撤销历史会清空 ——
跨图的撤销会把上一张图的内容写进当前图。

## AI 那一侧

AI 每一步都会在上下文里看到当前状态，不用它主动问：

| 通道 | 内容 |
|---|---|
| 每步注入 | 当前 Mermaid 全文（坐标行与格式说明行已滤掉；文本里的 `{{` 会拆成 `{ {`，原因见 `AGENTS.md`）；要看原文用 `arch_read` |
| 一句话总结 | `%% @summary` 单列成「**这张图讲的是**」；同图库别的图的总结也一并告知 |
| 元素留言 | 待递的留言单独列成一节，AI 读一次就消耗；历史不注入 |
| 代码锚点 | `%% @file` 逐条带校验结果，失效的带 ⚠ 与「不要照着用」 |
| 保鲜 `drift` | 「图上次落盘之后哪些锚点的文件改过了」「哪些目录有源码却没画到」，只有非空时才注入 |

四个工具：

| 工具 | 用途 |
|---|---|
| `arch_read` | 读当前图的源码（通常不必调，上下文里已有） |
| `arch_edit` | 增量改图，**推荐**；按顺序应用 op，不破坏你摆好的布局，遇到不存在的节点在 `problems` 里说明原因 |
| `arch_switch` | 切到另一张图（你的画布跟着切）；不存在时报错并列出可选 key |
| `arch_write` | 整图替换，只用于初稿或结构性重画；继承同 id 节点的旧坐标、代码锚点与一句话总结 |

### 安全靠「退得回去」

每次落盘留一份快照，随时可以退回 —— 所以不必因为怕改坏而不敢让 AI 动手。

- **谁改的分得清**：每条检查点带作者（AI / 用户 / 打开）、修订号、时间、节点 / 连线数、
  以及这次动了哪些节点；面板顶栏「历史 N」点开就是这条时间线。
- **退回是「重放」不是「撤销」**：把那一份正文重新装回文档并落盘，末尾**追加**一条「用户 · 回到检查点」——
  时间线只增不减，退回之后还能再往前走。界面上那 60 步 Ctrl+Z 是另一层：只管这一次会话里的手动编辑。
- **只在内存里，按文件分开存**（上限 50 份，内容逐字节相同不重复记）；**重启 dsh 会清空**。
- **写盘失败的那一次不进历史**，两个写工具此时返回 `ok: false` 并把原因写进 `problems`
  （内存已经回滚，回执还说「已更新」就是骗 AI）。

## 出问题去哪看

这个插件**对 console 一字不吐**（故障一律抛错），现场一律写进文件：

```
~/.dsh/arch-canvas/logs/arch-canvas-YYYY-MM-DD.log
```

数据目录跟着 dsh 的约定走（`$DSH_HOME`，没设才是 `~/.dsh`）。一行一个 JSON，能直接 `grep`；
按天分文件、超过 3 天自动清理；当日写满 8 MB 封顶。

- 记什么：`plugin.mount`（挂上了没、注册了几个工具 / 路由）、`doc.load` / `doc.switch`、
  `tool.arch_edit` / `tool.arch_write`（AI 改了什么、几个 op 没生效）、`tool.reject`（入参被拒）、
  `history.rollback`、`doc.absent`（项目里还没有图库，写被拒）、`rpc.fail`、
  `persist.fail`（落盘失败并已回滚）、`doc.warnings`。轮询这类高频成功路径**不记**。
- **画布存不下来**（状态栏「已改图，但写盘失败」）：先看当天日志有没有 `persist.fail`。
  写入受会话的 workspace-write 边界约束，所以插件必须把会话一起递下去；日志里同时有
  `sandbox.policy.missing`，说明这次写拿不到会话 —— 此时如实失败，不偷偷放宽围栏。
- **级别门槛**：`debug` / `info` / `warn` / `error`，缺省 `info`；`ARCH_CANVAS_LOG_LEVEL=debug`
  能把降级的巡检事件也写出来。
- 排查顺序：先看当天这份 `.log` 的尾部（挂载与最近一次 AI 改动就在末尾）。`persist.fail` 出现
  说明磁盘没写进去，而那一版改动**已经回滚**，内存与磁盘仍然一致。

## 已知短板

- **留言只挂节点**：连线、分组不能留言（连线 id 是位置派生的，不稳定）；一个节点只有一条留言，
  开不了讨论串。代码锚点同理。
- **一句话总结只有一句**：`%% @summary` 单行、500 字上限。
- **符号存在性靠字符串搜索**：`路径#符号` 只做一次全文 `indexOf`，不区分定义与引用，
  换名重构过的文件可能假阳性。
- **保鲜只认「变没变」**：指纹变了就提醒，改一行注释也算；基线是「图上一次落盘」那一刻；
  漏画只看目录、不逐个文件列。
- **连线是正交折线，但没有真正的路由器**：方块挤得很密时，线仍可能贴着别的方块走。
- **自动布局只是起点**：简单分层，交叉多了不如 dagre。
- **撤销历史只在内存里**：上限 60 步，切图时按设计清空，重启就没了
  （要跨会话回退用「历史」面板里的检查点）。
- **空白会话里没有入口**：画布是主窗口的一个子页，「对话」这张皮只在你有会话时才渲染。
- **`@` 候选按会话取**：某个会话里没打开过画布时，`@` 菜单里不会列出节点（打开一次就有）。
- **只有节点会高亮**：新增 / 删除的连线不参与。

## 代码在哪

```
src/host/        解析端：Mermaid ⇄ 图模型、文档状态与 op、落盘与检查点、图库扫描、锚点校验、日志
src/client/      画布端：渲染、拖拽与连线、检查器、源码页、导出、槽位注册
src/package/     装机形态的两半入口（host / client）
src/bootstrap/   动态 Package 形态的两段引导层（基本不变）
lib/             构建产物，入库（tarball 装到没网没 devDeps 的机器上也能直接用）
assets/          随包分发的 mermaid 运行时资源
skills/          随包 skill（按目录名自动发现）
.arch-canvas/    本仓库自己的框架图，随仓库提交，测试钉着它
test/            分片测试与守门人（入口 test/docs.baseline.mjs）
tools/build.mjs  拼接 src → dist 与 lib（分片顺序写在这里）
dist/            构建产物（不入库）
```

`src/host/*` 与 `src/client/*` 是**被拼接成一段函数体的分片**，不是模块 —— 里面不能出现 `import` / `export`，
文件名不带编号，拼接顺序由 `tools/build.mjs` 的 `HOST_PARTS` / `UI_PARTS` 声明。

分片的写法约束、RPC 与工具的注册面、图库扫描节奏、各项常量与不变式都由 `AGENTS.md` 与源码守着 ——
卡在哪先看 `AGENTS.md`，再看 `src/host/plugin.ts`（RPC 与工具的定义处）。
