# 架构画布（arch-canvas）

用户侧栏有一个「架构画布」面板，你和用户**在看同一张图**。用户拖图形，你读文本。

## 0. 先看写图开关 —— 默认是关的

**默认你只能读，不能写。** 宿主侧有一道硬闸门（`arch_write` / `arch_edit` 会被直接拒绝，
返回里会告诉你开关是关的）。只有下面两种情况你可以动图：

1. 用户**在画布面板顶栏点开了**「AI 只读」开关（点开后按钮显示「AI 可改图」）；
   当前状态每次都写在你的上下文里（`AI 改图开关：已打开 / 关闭`），**以那份为准**；
2. 用户**明确让你画/改**（「画一版」「补到图上」「把这个节点挪一下」），且开关是开着的。

开关关着时：**不要试、不要绕**（别用 `arch_write` 探一下、也别写文件），
把你想画的结构**用文字写在回复里**（需要的话贴一小段 mermaid 代码块），
并说一句「想让我直接改图就打开面板上的『AI 只读』开关」。

开关是**用户的**，不是你自己的：不要因为"这次任务需要"就假设它开着。

## 先记住三件事

1. **这张图表达的是「讨论中的逻辑框架」，不保证与代码一致。**
   不要拿代码去纠正它，也不要因为图上没有某个模块就断定它漏了。
   它是讨论的画布，不是代码的镜像 —— 用户可能故意只画了一条链路。
2. **当前那张图每一步都已经在你的上下文里了。** 不要凭记忆回答图相关内容；
   只有当上下文里那份可能过期、或要看**别的**图时，才调 `arch_read`。
3. **用户在图上动一下，下一步你就能看见。** 反过来，你改完图，用户画布会同步，
   而且**你改动过的节点会短暂高亮** —— 所以说明里点名节点 id 很有用。

## 四个工具怎么选

| 场景 | 用哪个 |
|---|---|
| 看当前图 | 上下文里就有；不确定时才 `arch_read` |
| 改局部（加一个节点、改个标签、连一条线、挪个位置） | **`arch_edit`** —— 默认选择（**需要开关打开**） |
| 画初稿 / 结构性重画 | `arch_write`（**需要开关打开**；会继承同 id 节点的旧坐标，但仍会散掉未被重声明节点的布局） |
| 用户正看着 A，你想看一眼 B | `arch_read` 带 `diagram` —— **只读不切**，不会动用户的画面 |
| 确实要和用户一起看另一张 | `arch_switch` —— 用户的画布会跟着切过去 |

**默认永远先想 `arch_edit`。** `arch_write` 存在的唯一理由是初稿和结构性重画；
用它去改一处细节，用户手动摆好的布局就散了 —— 这是这个工具最容易被用坏的地方。

`arch_edit` 一次可以传多个 op，按顺序执行；遇到问题不会静默失败，会在 `problems` 里说明原因
（比如「节点 x 已存在，改用 set_label」）。**先看 `problems` 再向用户汇报。**

### op 一览

`add_node` · `set_label` · `set_shape` · `set_link` · `move_node` · `remove_node` ·
`add_edge` · `remove_edge` · `set_edge_label` · `add_group` · `set_group` · `remove_group` · `set_direction`

形状：`rect` 矩形 / `round` 圆角 / `stadium` 胶囊 / `circle` 圆 / `diamond` 判定 /
`cyl` 数据库 / `hex` 六边形 / `sub` 子流程 / `asym` 旗形。

## 图的引用名（key）

图库**跟着项目走**：每个项目目录下一个 `.arch-canvas/`，每张图一个 `.mmd` 文件。
引用一张图用**相对项目根的 key**：

| key | 含义 |
|---|---|
| `主流程` | 根图库里的 `主流程.mmd` |
| `支付/对账` | 子项目 `支付` 的图库里的 `对账.mmd` |

`arch_switch` 的 `key`、`arch_read` 的 `diagram`、`set_link` 的 `link` 都用这个写法。
`arch_switch` 遇到不存在的 key 会**列出可选图名** —— 照着它说的写就行，别猜。

## 两条元数据注释，原样保留

图文件里有两种注释，**都是元数据，不是图的内容**：

```mermaid
%% @pos n1 120 40          ← 画布坐标（用户拖出来的）
%% @link n1 支付/对账       ← 这个节点下钻到另一张图
```

- **原样保留**，不要删、不要改、不要在回复里讨论它们。
- 删掉 `@pos` 只是让节点重新自动布局；删掉 `@link` 就是解掉一次下钻。
- `@link` 是「一个节点展开成一张图」的写法，比给图分层级更贴合讨论时的放大/缩小。
  用户说「这个能展开讲讲」时，可以考虑给他建一张新图并 `set_link` 连过去。

## 反面清单

- ❌ **开关关着还去写图**（试一下 `arch_write` 看看行不行 / 直接改 `.mmd` 文件绕过闸门）
- ❌ 自己判断"这次任务需要图"就假设开关开着 —— 开关是用户的
- ❌ 拿代码去「纠正」图上的表达（图上没画 ≠ 漏了）
- ❌ 用 `arch_write` 改一处细节，把用户摆好的布局冲掉
- ❌ 凭记忆描述图的内容（上下文里就有当前版本）
- ❌ 在回复里复述 `@pos` / `@link` 注释
- ❌ 用户看着 A，你 `arch_switch` 到 B 却没说要换（他会莫名其妙）
- ❌ 图是空的就大段猜，先看一眼再动手
